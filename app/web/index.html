Run a fixed, deterministic training scenario against isolated mock targets.

Controlled simulation boundary

This scenario uses synthetic input and a deterministic local training engine. It does not call an external AI provider, enable target profiles, or persist assessment results. A successful execution adds one audit-log entry.

SCENARIO AI-003

Agent Tool Misuse & Permission Enforcement

Compare a vulnerable mock agent with a protected mock agent when both receive four fixed synthetic tool requests. The protected agent applies an explicit tool allowlist and required-permission checks.

AI-003
Tool requests Four fixed synthetic attempts
Authorization model Allowlist + permission checks
Execution boundary In-memory mock agents only
Simulated tool boundary

The scenario models a sensitive-record read, a command execution request, an external request, and an access-control change. None of these actions is performed against a real system. No real shell, filesystem, network, or account operations are used.

Only the fixed AI-003 scenario can be run. User-supplied tools, commands, URLs, records, and permissions are not accepted. A successful run records one audit event only.

SCENARIO AI-004

AI Agent Memory Poisoning & Persistent Instruction Manipulation

Compare a vulnerable mock agent with a protected mock agent across two interactions. The scenario tests whether untrusted or modified memory can become a persistent instruction and influence later behavior.

AI-004
Memory lifecycle Two synthetic interactions
Trust validation Provenance + SHA-256 + HMAC
Protected behavior Validate, quarantine, re-check
SYNTHETIC MEMORY BOUNDARY

Only three fixed synthetic memory records are used. No personal memory, account data, external memory store, filesystem, network, or external AI provider is accessed. The HMAC key is embedded for demonstration only and is not production key management.

Only the fixed AI-004 scenario can be run. Client-supplied memory entries, source identifiers, prompts, and canaries are not accepted. Only one audit event is recorded; no assessment, test-run, finding, or evidence records are created.
